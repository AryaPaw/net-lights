В рабочей ветке готовится версия 1.7.0 на Rust и GPUI Kit. Новая нативная сборка пока не опубликована; GitHub Release содержит прежнюю реализацию. Для безопасного автоматического перехода сначала подготавливается исправление старого обновлятора 1.6.1.

Net Lights проверяет заданные контрольные адреса по HTTPS HEAD. Это показывает доступность этих адресов, а не всего интернета. Программа не меняет системные DNS, маршруты или сертификаты. Цвет каждой половины свой:

- **зелёный** — доступно (не меньше двух независимых подтверждений)
- **жёлтый** — ограничено (только одно подтверждение)
- **красный** — нет ответа
- **серый** — нет свежих данных
- **синий** — пауза в меню значка, обе половины

## Окно

Один щелчок по значку открывает окно. Кнопка закрытия прячет его обратно в трей; чтобы завершить работу, выберите «Выход» в меню значка.

Нативный интерфейс использует пять верхних вкладок: «Состояние», «Локации», «Диагностика», «Параметры» и «О программе». Оформление следует Fluent Design: компактные вкладки с голубым индикатором, единые размеры кнопок, системная типографика и собственный заголовок окна. В параметрах можно выбрать светлую, тёмную или системную тему. На широком окне слева доступны переходы к группам настроек; на узком остаётся одна прокручиваемая колонка.

На странице состояния текущая сводка отделена от истории. Два ряда провайдера и мира используют общую временную ось и подсказку; отметки смены страны помогают сопоставлять события по времени. По умолчанию ширина статусов соответствует их длительности; увеличение коротких отметок включается вручную. Выделение мышью временно увеличивает участок, кнопка «Весь период» возвращает выбранный период. Охват наблюдений показан отдельно от процента доступности. Раскрытие адресов и диагностика относятся к текущему состоянию; карточки исторических событий не подменяют его сегодняшними HTTP-ответами и задержками.

В разделе «Приложение» доступен выбор языка: «Как в системе», «Русский» или `English`. По умолчанию используется язык интерфейса Windows; для неподдерживаемого языка – английский. Выбор применяется сразу, включая подсказки и меню трея, и сохраняется после перезапуска. Язык не меняет записанную историю.

На вкладке «О программе» находятся версия с кнопкой копирования, ссылки на исходный код и выпуски, папка данных и лицензии компонентов. Значок страны в трее сохраняет пропорции букв; размер можно выбрать в параметрах.

## Локации

На вкладке «Локации» показаны история страны внешнего IP и частота её смен за выбранный период: 1, 3, 6, 12 или 24 часа, 3, 5 или 7 дней. При нормальной связи основной онлайн-источник `country.is` опрашивается каждые 10 секунд; после ошибок повторы реже. Если от него нет пригодного ответа, используется резервный `ipwho.is`. Базы V2Fly и IPLocate работают локально только для сравнения и не подменяют основной результат.

Точное время смены страны между проверками неизвестно. Чтобы посмотреть отдельные диагностические результаты источников, раскройте раздел «Debug: источники определения» под графиками; по умолчанию он свёрнут.

## Как пользуются

1. Скачайте установщик нужной версии со страницы [Releases](https://github.com/AryaPaw/net-lights/releases).
2. Запустите его. Права администратора не нужны.
3. Значок появляется в трее. По умолчанию программа запускается вместе с Windows; автозапуск можно выключить в «Параметрах».

Если включено автообновление, программа получает установщик с GitHub и запускает его в фоне. Настройка «Автообновление» находится в «Параметрах».

Переход на нативную версию выполняется через 1.6.1 с исправленным обновлятором. Адрес GitHub `releases/latest` закрепляется за 1.6.1 для старых клиентов. Версия 1.6.1 и нативные версии выбирают последний стабильный выпуск от 1.7.0 из ограниченного списка релизов; предварительные выпуски игнорируются. Скачивание новой версии вручную доступно на общей странице Releases.

## Установка

Нужна **Windows 11 x64**. Отдельный .NET Runtime для нативной сборки не нужен, права администратора для установки не требуются. Файл: `NetLights-Setup-win-x64-*.exe`.

## Интервалы проверок и трафик

В «Параметрах» в блоке «Проверки и трафик» можно выбрать интервал доступности от 2 секунд до 5 минут. По умолчанию – 5 секунд для каждой группы; сайты внутри группы проверяются по очереди. Выбор сохраняется и применяется без перезапуска. При сбоях, запуске и смене сети возможны дополнительные проверки для подтверждения состояния. Более редкий опрос снижает трафик, но увеличивает задержку обнаружения изменений.

Интервал определения страны настраивается отдельно: 10, 15, 30 или 60 секунд. На странице «Диагностика» в разделе «Debug: трафик приложения» показаны переданные и полученные TCP-данные с запуска, включая TLS. История счётчиков не хранится. Загрузки баз и установщиков учитываются отдельно; DNS, IP-заголовки и повторная передача TCP в счётчики не входят. После десятиминутного замера обычного расхода программа определяет порог предупреждения. Прогноза месячного расхода нет.

## Сборка

Нужны Rust 1.98.1 (MSVC), Visual Studio Build Tools с C++ и Windows SDK. Точная версия Rust и компоненты закреплены в `rust-toolchain.toml`. Интерфейс использует GPUI Kit 0.9.1, без WebView. Существующая реализация C# сохранена в `src/` как источник контрактов миграции.

```ps1
pwsh -File scripts/verify.ps1
pwsh -File scripts/run-local.ps1 -NoStart
```

`scripts/verify.ps1` запускает проверку формата, строгий Clippy, тесты рабочего пространства и проверку готовых exe. Настоящий монитор запускается дважды в изолированном профиле: проверяются реальные сетевые пробы, сигнал готовности, сохранность настроек и обеих историй, штатный выход. Первый сбой останавливает проверку; результаты остаются в `TestResults`. Этот же вход используется в CI. Дополнительный `-Legacy` запускает прежние наборы .NET, которые отдельно не подтверждают качество Rust-сборки.

`scripts/run-local.ps1 -NoStart` собирает приложение и агент обновления в новой папке, штатно завершает только локальную копию и заменяет её файлы транзакционно. `-NoStart` отключает последующий запуск. Установленную копию в AppData этот скрипт не заменяет.

`pwsh -File scripts/verify.ps1 -NativeUI` проверяет запущенное окно через UI Automation на одноразовой GitHub-hosted Windows VM: пять страниц на русском и английском, восемь периодов, переключатели, селекторы, общую подсказку, выбор события, увеличение диапазона, раскрытие адресов, прокрутку и сохранение размера после перезапуска. Отдельно проверяются клавиатурная навигация вкладок, компоновка настроек на широком и узком окне, версия и копирование на странице «О программе». Результат относится к фактическому DPI сеанса. Для него нужен `uv`.

Локальные интерактивные UI-прогоны через подключённую Windows Sandbox заблокированы до её запуска: RDP-клиент может синхронизировать курсор гостя с курсором пользователя. Проверка гостевой учётной записи этого не предотвращает. Прямые `SetCursorPos` и `SendInput` в таком режиме также запрещены в Python runner; повторного наведения при смещении курсора нет. Полный локальный gate, включая функциональный UI для покрытия, останавливается на этом ограничении и не получает `PASS`. Проверки установщика без перемещения мыши остаются отдельными сценариями.

Для покадровой проверки вкладок в CI тест временно включает анимации в одноразовой VM. Исходное значение восстанавливается в `finally`, в том числе при ошибке. Проверяются промежуточные положения индикатора и быстрые повторные переключения, а не только конечные снимки.

`pwsh -File scripts/verify.ps1 -ResourceRun` дополнительно запускает часовой ресурсный прогон с максимальной историей и двумя настоящими GeoIP-базами. Анализ исключает прогрев и проверяет устойчивый рост private bytes, GDI, USER и handles; короткие или неполные измерения не получают `PASS`. CPU и working set сохраняются для сравнения. Неудачная загрузка баз также не считается выполненным ресурсным прогоном.

Настоящие установка, обновление, откат и восстановление обоих значков после перезапуска Проводника проверяются отдельно через `scripts/test-sandbox-update.ps1` в собственной Windows Sandbox. Скрипт отказывается использовать или закрывать чужую Sandbox. Результаты Sandbox, UI и ресурсного прогона нельзя подменять unit-тестами.

Промежуточная C#-версия 1.6.1 подготавливается командой `pwsh -NoProfile -File scripts/prepare-bridge.ps1 -Verify -Publish -Installer -DownloadBaseline`. Она воспроизводит опубликованный исходный commit 1.6.0, применяет ограниченный патч из `compat/bridge-1.6.1.patch`, прогоняет прежние тесты и собирает установщик в новой папке `artifacts`. Здесь `-Publish` означает локальную упаковку exe; команда не создаёт коммит, тег или GitHub Release и не меняет установленную программу. `scripts/test-bridge-update.ps1` проверяет отдельную реальную цепочку 1.6.0 → 1.6.1 → 1.7.0, включая исходный агент 1.6.0, ошибки установки, отказ сигнала готовности, откат и сохранность данных.

Настройки и обе истории совместимы с прежней реализацией и находятся в `%LOCALAPPDATA%\NetLights`. Истории хранятся семь дней; атомарная запись и `.bak` защищают последнюю полную копию. При нечитаемых основном и резервном файлах запись соответствующего хранилища блокируется, исходные файлы сохраняются. Ограниченный журнал жизненного цикла находится в подпапке `logs` и не содержит IP и секретов.
