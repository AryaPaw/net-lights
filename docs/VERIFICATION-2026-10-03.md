# Проверка Net Lights – 03–04.10.2026

Отчет относится к текущей незакоммиченной рабочей копии, версии 1.5.0. Установленная копия в `%LOCALAPPDATA%\Programs\NetLights` и опубликованные релизы не изменялись. Результат не является подтверждением полной готовности к выпуску.

## Исправления, внесенные после аудита

- Исправлена ошибка компиляции в `NetLightsContext`.
- Последовательная обработка heartbeat и системных сетевых событий исключает конкурентное изменение состояния доступности.
- Завершение и сборка истории согласованы с активными записями; ошибки жизненного цикла и сохранения записываются в ограниченный постоянный `RuntimeJournal` без IP и секретов.
- Ограничены чтение чрезмерных файлов истории, настроек, pending-update и журнала GeoIP-бюджета; поврежденные данные не должны безусловно проходить в десериализатор.
- Усилены восстановление истории/настроек, атомарная запись и резервные копии; для автостарта переносная сборка не должна переписывать путь установленного приложения.
- В обновлении добавлены проверки хеша на пути к установщику и резервирование/откат файлов установки. Это подтверждено тестами компонентов, но не настоящим установщиком в Sandbox.
- Исправлена привязка результата `ipwho.is` к неподтвержденному IP.
- Исправлены HTTPS-тесты: предыдущая fixture зависела от нестабильной временной цепочки сертификатов. Новая fixture использует самоподписанный сертификат с server-auth: публичная копия служит доверенным корнем, а копия с ключом используется сервером. В этой среде операции с ключом Schannel требуют повышенного запуска тестов.
- Для плотных событий истории локаций добавлены групповые подписи без наложения; подсказка группы показывает точные отдельные события, а не маскирует их агрегатом.
- В `IPLocateCountryDatabase` устранена подтвержденная копия входного ZIP через `ToArray()`: read-only `MemoryStream` теперь читает исходный ограниченный `byte[]`. Размер локального архива при осмотре был 8 754 510 байт, поэтому эта копия добавляла около 8,35 MiB к временному пику разборки. Проверка подтверждает, что парсер не меняет исходный массив.
- Истории доступности и локаций теперь сериализуются напрямую в `FileStream`, без предварительной полной UTF-16 JSON-строки. Формат файлов не изменился; существующие roundtrip-проверки остались зелеными.
- Устранено и второе полное дублирование при сохранении локаций: строки истории больше не собираются заранее в два новых списка DTO; сериализатор перечисляет проекции снимка напрямую. Для истории доступности убрана промежуточная копия списка `Spans`. Roundtrip, восстановление и расширенные записи проверены повторными Integration-тестами.
- Замерочный скрипт ресурсов изменен после обнаруженного сбоя процесса сбора: теперь каждая строка немедленно сбрасывается в CSV и существующий файл не перезаписывается. Обычный короткий запуск записал 3/3 строки, а отдельная проверка Ctrl+C сохранила 3 уже записанные строки (`artifacts/evidence/netlights-resources-20261004-interrupt-smoke.csv`).

Рабочие файлы до начала работы уже содержали изменения пользователя и прежних этапов. Эти изменения сохранены; ничего не сбрасывалось.

- Добавлены интеграционные проверки подписей всех состояний доступности и структурированных сетевых ошибок, а также пояснений строк endpoint (пауза, устаревшие данные, отсутствие результата, ошибка и дополнительное подтверждение). Они фиксируют пользовательский вывод, а не внутренние свойства контролов.
- Исправлен coverage gate: суммарный порог 80% теперь действительно блокирует проверку, как требует инструкция поставки; ранее скрипт только печатал общий процент. После новых проверок итоговое покрытие критических сборок – 80,12%.

## Ресурсы процесса

Проведены три профиля скриптом `scripts/measure-local-resources.ps1` с интервалом 10 секунд; CSV включает private bytes, working set, handles, GDI, USER и CPU.

1. `artifacts/evidence/netlights-resources-20261004-hour.csv` – до потоковой записи, окно было скрыто в трее: 361 точка за 60,12 мин; private bytes min/mean/max 165,1/193,4/260,2 МиБ; среднее первой/последней десятины 165,7/219,6 МиБ; working set mean/max 255,3/315,8 МиБ; CPU mean/max 0,058/0,27%; handles 669–754, GDI 34, USER 27–29.
2. `artifacts/evidence/netlights-resources-20261004-streaming-hour.csv` – после потокового JSON, окно было видно: 361 точка за 60,14 мин; private bytes min/mean/max 124,7/138,1/157,1 МиБ; среднее первой/последней десятины 128,5/152,1 МиБ; working set mean/max 214,3/228,4 МиБ; CPU mean/max 0,211/0,99%; handles 694–871, GDI 58–80, USER 80–133. Пик снизился примерно на 103 МиБ, но устойчивый рост к концу остался.
3. `artifacts/evidence/netlights-resources-20261004-streaming-rows-hour.csv` – после удаления материализации списков DTO, окно видно, PID 8020. 361 точка за 60,14 мин: private bytes min/mean/max 96,5/127,0/155,0 МиБ; среднее первой/последней десятины 101,6/144,7 МиБ; working set mean/max 194,1/213,8 МиБ; CPU mean/max 0,091/0,23%; handles 717–829, GDI 58–69, USER 80–89. После прогрева и двух снижений при сборке мусора последние 15 минут колебались около 139–149 МиБ; последние 5 минут – 144,8 МиБ в среднем.

Профиль №2 показывал рост последней десятины на 23,6 МиБ относительно первой; устраненная материализация DTO была реальным источником временных аллокаций. В профиле №3 частная память сначала выросла до 155 МиБ, затем дважды снизилась примерно до 112 и 140 МиБ; в последние 15 минут не наблюдался продолжающийся линейный рост. Это совместимо с прогревом и удержанием памяти .NET после крупных временных аллокаций, но счетчики managed heap недоступны, поэтому причину и отсутствие скрытой утечки этим профилем доказать нельзя. Локальная IPLocate-база содержит 2 138 907 сетей: архив 8,75 MB, CSV после распаковки около 80,1 MB, индексные массивы занимают примерно 25,7 МиБ; V2Fly также загружается в память. Эти таблицы объясняют часть постоянного расхода, но не весь разрыв с прежними ~30 МиБ. GDI, USER и handles оставались в ограниченном диапазоне. Это был часовой профиль видимого окна при обычном фоне, не стресс-нагрузка; он не заменяет UI-soak и не объясняет пользовательское прежнее наблюдение около 30 МиБ.

## Критические сценарии, которые остаются неподтвержденными

1. Реальное обновление установленного приложения настоящим Inno Setup внутри Windows Sandbox: успех, отказ на разных этапах, rollback, сохранность данных и подтверждение работы нового мониторинга – NOT RUN. Предыдущая попытка запустить этот сценарий была остановлена auto-review; причина отказа в доступных следах не сохранена, повторно запуск не предпринимался. Модульные/process тесты агента с тестовым приложением этого не заменяют.
2. Полная проверка восстановления после отказа запуска новой установленной версии и зависшего установщика – NOT RUN в Sandbox.
3. Причина прежнего самопроизвольного закрытия приложения не установлена. Журнал теперь сохраняет больше сведений о следующих запусках и штатном завершении, но ретроспективно объяснить уже случившийся выход невозможно.
4. Ресурсная проверка на 60 минут выполняется в профиле простоя; длительная автоматизированная нагрузка с многократным открытием вкладок, движениями указателя, максимальной историей, обновлением GeoIP и сном/пробуждением – NOT RUN.
5. Неограниченность/объединение канала команд монитора: всплеск очереди и устойчивый рост памяти не воспроизведены; это остаточная область наблюдения, а не доказанная утечка.
